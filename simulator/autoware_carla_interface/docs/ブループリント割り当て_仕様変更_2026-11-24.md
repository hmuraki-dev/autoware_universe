# ブループリント割り当ての仕様変更(2026-11-24)

交通シム(Vissim)の車両モデルに CARLA のブループリントを割り当てる処理(`carla_fleet.assign`)の仕様を、次の 2 点で変えた。
別の環境(SUMO 構成のブランチなど)の割り当て処理に同じ変更を入れるための説明書。

1. **幅の上限(太い側の許容)を車種カテゴリごとに持てるようにし、大型車を広げた**(0.35 m → 0.45 m)
2. **ブループリントの分類(`base_type`)を判定に加えた**(乗用車には乗用車、トラックにはトラック…)

どちらも規則ファイル(YAML)で指定する。指定しなければ今までどおりに動く(後方互換)。

| 項目 | 場所(このブランチ `feature/vissim_windows_co-sim`) |
|---|---|
| 割り当て処理 | `src/autoware_carla_interface/carla_fleet.py` |
| 新しい規則(0.9.16_jp 用) | `src/autoware_carla_interface/data/carla_fleet/carla_variant_rules_carla0.9.16_jp.yaml` |
| 実メッシュの計測結果(0.9.16_jp) | `src/autoware_carla_interface/data/carla_fleet/mesh_measurements_carla0.9.16_jp.json` |
| テスト | `test/test_carla_fleet.py` |
| コミット | `88bc3bc52`(処理・規則・計測結果・テスト)、`8897860cd`(Town10HD の表の作り直し) |

---

## 1. 変えた理由

CARLA 0.9.16_jp で、修正版の日本車(`vehicle.jp.*`)を LiDAR で測り直した結果:

| ブループリント | 分類 | LiDAR の外形 L×W [m] | Vissim のモデル L×W [m] | dW [m] |
|---|---|---|---|---|
| vehicle.jp.alphard | car | 4.971 × 2.160 | 1001 Alphard 4.950 × 1.850 | +0.310 |
| vehicle.jp.minivan | car | 4.725 × 2.080 | 1002 NOAH 4.710 × 1.736 | +0.344 |
| vehicle.jp.taxi | car | 4.399 × 1.872 | 1003 JPN Taxi 4.400 × 1.696 | +0.176 |
| vehicle.jp.large_truck | truck | 12.171 × 2.864 | 1021 GIGA 11.810 × 2.490 | +0.374 |
| vehicle.jp.route_bus | bus | 10.699 × 2.880 | 1031 Erga 10.430 × 2.484 | +0.396 |
| vehicle.jp.tour_bus | bus | 12.109 × 2.840 | 1032 GALA 11.990 × 2.490 | +0.350 |

dW ＝ LiDAR の幅 − モデルの幅。

- **LiDAR の外形はミラーの先端まで含む**。Vissim のモデルとカタログの全幅はミラーを含まない(GALA の公式の全幅 2,490 mm もミラーなし)。
- 大型車はミラーの張り出しが大きく、dW が +0.35〜+0.40 m になる。そのため、元の上限 +0.35 m を超えて候補から外れ、carlacola を 3 台重ねる割り当てになっていた。
- 上限を広げるだけでは足りない。元の規則は分類を見ずに長さの近い車を選ぶので、トラック(GIGA 11.81 m)に、長さの近いバス(jp.tour_bus 12.11 m)が割り当たってしまう。

## 2. 仕様(変更後)

### 2.1 規則ファイルの項目

```yaml
# 太い側の許容。数値 1 つ(全カテゴリ共通。今までどおり)か、車種カテゴリごとの表
width_over_tolerance_m: {CAR: 0.35, HGV: 0.45, BUS: 0.45, TRAM: 0.45, BIKE: 0.35}

# 細い側の許容(今までどおりカテゴリごと。変えていない)
width_under_tolerance_m: {CAR: 0.35, HGV: 0.10, BUS: 0.10, TRAM: 0.10, BIKE: 0.35}

# 新規・省略可。車種カテゴリごとに、1 体で表すときに許す base_type の一覧
blueprint_classes:
  CAR: [car, van, ""]
  HGV: [truck]
  BUS: [bus]
  TRAM: []
  BIKE: [motorcycle, bicycle]
```

- **車種カテゴリ**は、Vissim の vehicleType の category(`CAR`・`HGV`・`BUS`・`TRAM`・`BIKE`)。
- **`width_over_tolerance_m`**
  - 数値なら、全カテゴリで共通の値。
  - 表なら、モデルのカテゴリの値を使う。
- **`blueprint_classes`**
  - 省略すると、分類では絞らない(今までどおり)。
  - 書くと、モデルのカテゴリが許す `base_type` を持つブループリントだけが、1 体で表すときの候補になる。
- 表の形の項目は 3 つとも、1 つのモデルを複数のカテゴリが使うときの扱いが同じ。
  - 幅の許容: 最も厳しい(小さい)値を使う。
  - `blueprint_classes`: すべてのカテゴリが許す `base_type` だけを候補にする。
  - 表に無いカテゴリがあると止める(`variant_category_unknown`)。

### 2.2 判定の流れ

モデル 1 つ(長さ L、幅 W、カテゴリの集合)について、次の順に試す。

1. **1 体で表す**: 次の条件をすべて満たすブループリントの中から、|dL| が最小のものを選ぶ。同点なら |dW|、次に名前順。
   - 除外リスト(`excluded`)に無い
   - **【新】分類が合う**(`blueprint_classes` があるときだけ)
   - |dL| ≤ `length_tolerance_m`(0.75)
   - −under ≤ dW ≤ **【変】over**(over はモデルのカテゴリの値)
2. **fallback を重ねる**(1 が無いとき): モデルが fallback(carlacola、5.109 m)より長く、fallback の幅が 1 と同じ許容に入れば、ceil(L / 5.109) 体を重ねる。
   - **fallback は分類では絞らない**。carlacola の分類は truck だが、バスのモデルにも使う。
3. **どちらもできなければ、割り当てなし**(`None`)。表の生成ツールは `variant_model_empty` で止まり、表を書かない。黙って別の車にはしない。

### 2.3 分類の比べ方

- 比べる値は、ブループリントの属性 `base_type`。実メッシュの計測ツール `measure_blueprint_mesh.py` が計測結果に記録している。
- 前後の空白を除き、大文字・小文字を区別しないで比べる。たとえば fusorosa の値は `"Bus"`。
- 0.9.16_jp の `base_type` には、次のくせがある。規則はこれに合わせてある。
  - `bmw.grandtourer`・`mini.cooper_s` は `base_type` が空。乗用車なので、CAR に `""` を許す。
  - `ford.ambulance`・`mercedes.sprinter`・`volkswagen.t2` は `van`。大きな乗用車のモデルに合うことがあるので、CAR に `van` を許す。
  - CARLA に路面電車は無いので、TRAM は `[]` にした(1 体では表さず、fallback だけ)。

### 2.4 エラー

| コード | いつ | 新規/既存 |
|---|---|---|
| `variant_base_type_unmeasured` | `blueprint_classes` があるのに、候補のブループリントの計測結果に `base_type` が無い。evidence に `blueprint` | 新規 |
| `variant_category_unknown` | モデルのカテゴリが、`width_over_tolerance_m`(表のとき)・`width_under_tolerance_m`・`blueprint_classes` のどれかに無い | 既存(対象を広げた) |
| `variant_model_empty` | 割り当てられないモデルがある(生成ツールが出す) | 既存 |

## 3. コードの変更(`carla_fleet.py`)

### 3.1 計測結果の読み込みで `base_type` を残す

```python
def load_mesh(path) -> tuple[dict, dict]:
    ...
    mesh = {}
    for row in rows:
        if "mesh_width_m" not in row or "mesh_length_m" not in row:
            continue

        if "base_type" in row:      # ブループリントの分類(規則の blueprint_classes で使う)
```

### 3.2 カテゴリごとの値の取り出しと、分類の判定(追加)

```python
def _per_category(table, categories):
    """カテゴリごとの表から、モデルのカテゴリの値を並べる。表に無いカテゴリがあれば止める。"""
    unknown = sorted(set(categories) - set(table))
    if not categories or unknown:
        raise VariantError("variant_category_unknown", categories=sorted(categories), unknown=unknown)
    return [table[category] for category in categories]


def width_under_tolerance(rules, categories) -> float:
    """細い側の許容。複数のカテゴリが使うモデルは最も厳しい値。"""
    return min(float(value) for value in _per_category(rules["width_under_tolerance_m"], categories))


def width_over_tolerance(rules, categories) -> float:
    """太い側の許容。数値 1 つなら全カテゴリ共通。カテゴリごとの表なら、複数のカテゴリが使うモデルは最も厳しい値。"""
    table = rules["width_over_tolerance_m"]
    if not isinstance(table, dict):
        return float(table)
    return min(float(value) for value in _per_category(table, categories))


def class_allowed(rules, categories, body, blueprint=None) -> bool:
    """ブループリントの分類(base_type)が、モデルのカテゴリに合うか。fallback には使わない。"""
    table = rules.get("blueprint_classes")
    if table is None:
        return True
    if "base_type" not in body:
        raise VariantError("variant_base_type_unmeasured", blueprint=blueprint)
    base_type = str(body["base_type"]).strip().lower()
    return all(base_type in {str(name).strip().lower() for name in allowed}
               for allowed in _per_category(table, categories))
```

## 4. 別の環境に入れる手順

1. **コードを直す**: 3 章の変更を、その環境の `carla_fleet.py`(または同じ役割のファイル)に入れる。差分は `git show 88bc3bc52 -- src/autoware_carla_interface/carla_fleet.py` で見られる。
2. **計測結果に `base_type` があるか確かめる**: `blueprint_classes` を使うなら、計測結果の各行に `base_type` が要る。
   - `measure_blueprint_mesh.py` は記録しているので、同じツールで測った結果ならそのまま使える。このブランチの 0.9.15 用・0.9.16_jp 用の計測結果には入っている。
   - 無ければ測り直す。
3. **規則ファイルを用意する**:
   - その環境の CARLA が 0.9.16_jp なら、`carla_variant_rules_carla0.9.16_jp.yaml` をそのまま使える。
   - 違う CARLA なら、既存の規則に `width_over_tolerance_m` の表と `blueprint_classes` を足す。
   - 既存の規則を書き換える代わりに新しいファイルにすると、その規則で作った既存の表に影響しない。表は自分の規則のパスと sha256 を記録しているため。
4. **割り当て表を作り直す**: `tools/carla_fleet/build_carla_variants.py` を新しい規則で実行する。
   - 規則を変えると、ブリッジは起動時の sha256 の照合(`variant_source_changed`)で止まる。その規則を使う表は、すべて作り直す。
5. **ビルドし直す**: 新しく作ったファイル(規則・表)は、`colcon build --symlink-install` でもビルドし直すまで install 側に入らない。
6. **テストを足す**: 5 章の観点。

## 7. 注意

- **自動二輪の上限 0.35 m には根拠が無い**。移植元が全車種に使っていた値を、そのまま残しただけ。
  - バイクのミラーはハンドルの先にあり、車体の幅からほとんど出ない。
  - MT-07 → kawasaki.ninja は dW −0.032 m(細い側)で、太い側の上限は使われていない。
  - 二輪の上限を詰めるかどうかは、二輪の dW を測ってから決める。
- **0.45 m の根拠**は、測った大型車の dW の最大(+0.40 m、route_bus)に 0.05 m の余裕を足した値。ほかの CARLA のバージョンや車両では測り直して決める。
- **`blueprint_classes` を CARLA の版の違う規則に使うとき**は、その版の `base_type` の値(空、大文字、van など)を計測結果で確かめてから一覧を決める。
