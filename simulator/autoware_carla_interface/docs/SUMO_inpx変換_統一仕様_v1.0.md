# Vissim inpx → SUMO 変換 統一仕様 v1.0

CARLA(0.9.16) 環境(このリポジトリの`tools/sumo_inpx/`)と CARLA(0.10) 環境(SBIR_sim の`sumo/`)で、
Vissim の`.inpx`から SUMO のファイルを作るときの規則をそろえるための仕様。

- 作成: 2026-11-26
- 対象: 車の需要(段階①)、歩行者(段階②)、横断歩道と歩行者信号(段階③)、信号制御の数
- 各環境の今の対応状況は 9 章。CARLA(0.10) 側の変更点は`SUMO_inpx変換_統一仕様_CARLA0.10側の変更点.md`

## 0. 用語

| 用語 | 意味 |
| --- | --- |
| 止める | ツールが`Error: <理由>`を出し、ファイルを書かずに終わる。写せない設定に気づけるようにする |
| 網 | SUMO の`.net.xml` |
| 0.9.16 / 0.10 | CARLA(0.9.16) 環境 / CARLA(0.10) 環境 |
| 決定点 | Vissim の経路決定・希望速度決定が置かれたリンクの位置 |

## 2. 車の需要(段階①)

### 2.1 車両入力

| 項目 | 規則 |
| --- | --- |
| 出す位置 | 流入リンクの始点を、流入リンクに対応する edge に射影した位置(`departPos`) |
| 台数 | 流量 [台/h] を平均とするランダム到着(ポアソン到着) |
| 止める | 時間帯が 2 つ以上 / 流量の種類が Stochastic でない |

### 2.2 経路(静的経路の経路決定)

| # | 項目 | 規則 |
| --- | --- | --- |
| R1 | 経路決定の場所 | 流入リンクにあるものだけを扱う。流入リンク以外にあるときは止める(途中で経路を受け取る車は写せない) |
| R2 | 1 つの流入リンクの経路決定 | 1 つだけ。2 つ以上あるときは止める |
| R3 | 対象の車両クラス | 全車種(`allVehTypes="true"`)だけ。一部の車両クラスだけのときは止める |
| R4 | 経路の割合 | `relFlow`の割合。時間帯が 2 つ以上あるときは止める。割合 0 の経路は使わない |
| R5 | edge 列 | 経路のリンク列(コネクタを含む)の線から「リンクの半幅の最大 + 1 m」以内を通る edge をたどり、行き先の近くに着く edge 列をすべて探す。たどる順は edge の ID の順の深さ優先 |
| R6 | 分岐 | 1 つの経路で edge 列が分かれるときは、分岐ごとに等分する |
| R7 | 行き先 | 行き先リンクの`destPos`の位置(無ければ行き先リンクの終点)で消える(`arrivalPos`)。行き先が交差点の中(内部 lane の上)にあるときは、交差点を出た edge の頭で消える |
| R8 | 着けない経路 | SUMO の網で着く edge 列が無い経路は、同じ流入の残りの経路に割合を寄せ、出力の先頭のコメントに書く。どの経路も着けないときは止める |
| R9 | 経路決定の無い流入 | 車 1 台ごとに、分岐ごとに次の edge を等しい確率で選ぶ。網の出口(次の edge が無い)か、決めた長さ(既定 2000 m)に達した edge の終わりで消える |

### 2.3 希望速度決定

| # | 項目 | 規則 |
| --- | --- | --- |
| S1 | 当てはめる車 | 走る edge 列が決定点を通る車(経路決定の無い車も含む)。出発位置より後ろの決定点は通らないとみなす |
| S2 | 当てはめ方 | 決定点が指定する車両クラスの車両タイプに、変更後の希望速度分布を**出発時から**使う(SUMO の車は走行中に vType を変えられない。Vissim は決定点を通ったときに切り替わる) |
| S3 | 決定点を 2 つ以上通る | 走る順で最初に通る決定点の分布を使う。2 つ目以降は使わない |
| S4 | 車線ごとの決定点 | 同じリンクの全車線で同じ分布であること。違うときは止める。ただし網が 1 車線ずつ(1 lanelet = 1 edge)の環境では、決定点の車線を横の並び順で edge 列に対応付けてよい(8 章) |
| S5 | コネクタの上の決定点 | 止める |

### 2.4 車種・寸法・加減速・運転挙動(両環境で同じ。確認のため)

| 項目 | 規則 |
| --- | --- |
| 車種 | 車両タイプのカテゴリ CAR → `passenger`、BUS → `bus`、BIKE → `motorcycle`。HGV は名前で「トラック」→ `truck`、「トレーラー」→ `trailer`(`guiShape="truck"`)。それ以外は止める |
| 車両構成 | 相対交通量 × 3D モデルの割合 × 希望速度の区間を`vTypeDistribution`の確率にする。CARLA に車体の無い vClass は割合 0 にしてよい(8 章) |
| 希望速度分布 | 区間ごとの vType。`speedFactor="normc(中央,100,下端,上端)"`、`desiredMaxSpeed="1"`(地図の制限速度に縛られない) |
| 寸法 | 3D モデルの長さ・幅・高さ。連結車は全長 1 本の箱 |
| 加速度・減速度 | `accel` = 希望加速度の 0〜60 km/h の平均、`decel` = 希望減速度(50 km/h)、`emergencyDecel` = 最大減速度(50 km/h) |
| 運転挙動 | Wiedemann 74 だけ(`carFollowModel="Wiedemann"`、`minGap` = ax)。全リンクが同じ運転挙動でないときは止める |

## 3. 歩行者(段階②)

| # | 項目 | 規則 |
| --- | --- | --- |
| P1 | 出す位置 | 歩行者入力の待ち場所(area)の歩道`ped_area<area の番号>`の中のランダムな位置(`departPos="random"`) |
| P2 | 人数 | 流量 [人/h] を平均とするランダム到着。時間帯が 2 つ以上 / Stochastic でないときは止める |
| P3 | 行き先 | 歩行者の静的経路(待ち場所 → 待ち場所)の行き先の歩道。経路の割合で分ける |
| P4 | 歩行者の種類 | 歩行者タイプ × 3D モデル(寸法の同じモデルは 1 つにまとめる)× 希望速度の区間の vType(`vClass="pedestrian"`) |
| P5 | 歩道が無い網 | 歩行者を入れずに続け、出力の先頭のコメントに書く(止めない) |
| P6 | 車が歩行者に譲る距離 | 車の vType の`jmCrossingGap` = 歩行者と車の競合エリアの「前の余裕」の最大 [s] × 歩行者の最大の希望速度 [m/s] + crossing を延ばした長さ(4 章の X3) |

## 4. 横断歩道(段階③)

| # | 項目 | 規則 |
| --- | --- | --- |
| X1 | 位置と幅 | Autoware の地図(lanelet2)の横断歩道(`subtype=crosswalk`の lanelet)の中心線と幅(D2) |
| X2 | 作る横断歩道 | Vissim の歩行者リンク(コネクタでないもの)ごとに、中ほどが lanelet2 の横断歩道の中心線の近く(半幅 + 1 m)にあり、向きが 30 度以内の横断歩道を対応付ける。複数本を扱う(D3)。対応する横断歩道が無い(または 2 つある)歩行者リンクがあるときは止める |
| X3 | 長さ | 地図の横断歩道の両端から 1 m ずつ延ばす(信号待ちの人が地図の横断歩道の外に立つように) |
| X4 | 渡る車道 | 横断歩道の中心線の近く(8 m 以内。中心線の端から 2 m まで)で交差点に入る・出る、横断歩道と 45 度以上交わる車の edge。1 つの交差点に集まらないときは止める(2026-11-26。0.10 の「横断歩道の多角形を通る内部 lane の前後の edge」は、Town10HD の大きな交差点で別の枝の edge を拾ったので変えた) |
| X5 | 優先 | crossing を`priority="true"`にする(Vissim の競合エリアで歩行者が優先。信号の青が同時でも、渡る車が歩行者に譲る) |
| X6 | 歩道 | 横断歩道の端の近く(15 m 以内)に待ち場所(歩行者入力・歩行者の経路が使うエリア)があれば、待ち場所の外側の端から、横断歩道の延長線上に、延ばした横断歩道の端の 0.5 m 手前まで(D6)。待ち場所が延長線上に無いときは止める。待ち場所の無い端は網の今の歩道につなぐ(網に歩道があるとき)。1 つの待ち場所の歩道は 1 本 |
| X7 | 車道 | 車道の lane は歩行者を通さない(`--default.disallow pedestrian`) |
| X8 | 止める | 地図の横断歩道を通る車の connection が無い / 横断歩道の両端が同じ待ち場所に近い |

## 5. 歩行者信号(段階③)

| # | 項目 | 規則 |
| --- | --- | --- |
| W1 | 対応付け | 位置で対応付ける(D4)。歩行者信号灯 → 乗っている歩行者リンク → X2 で対応付けた横断歩道 → SUMO の crossing の linkIndex |
| W2 | 1 本の横断歩道の信号 | その横断歩道の歩行者信号灯は、同じ信号グループであること。違うときは止める |
| W3 | 信号の無い横断歩道 | 信号の無い交差点の横断歩道は、信号の無い crossing(歩行者優先)にする。信号のある交差点の横断歩道に歩行者信号灯が無いときは止める(SUMO では信号のある交差点の crossing は信号の linkIndex を持つため) |
| W4 | 色 | 青 → `G`、青点滅 → `r`(渡り始めない。渡っている人は渡り切る)、赤 → `r` |
| W5 | linkIndex | crossing の linkIndex は、車のリンクの後ろに付く(車の linkIndex は変わらない) |
| W6 | 交わる車 | 横断歩道が青の間、横断歩道と交わる(交差点の foes)車の青のリンクは`g`(譲る) |

## 7. 止める条件(まとめ)

| 区分 | 止める条件 |
| --- | --- |
| 車両入力 | 時間帯が 2 つ以上 / Stochastic でない |
| 経路 | 流入リンク以外の経路決定 / 1 つの流入リンクに 2 つ以上の経路決定 / 一部の車両クラスだけの経路決定 / 時間帯ごとの割合 / どの経路も着けない |
| 希望速度決定 | コネクタの上 / 同じリンクで車線ごとに違う分布(網が 1 車線ずつの環境を除く) |
| 車種・挙動 | 知らないカテゴリ・HGV の名前 / Wiedemann 74 でない / リンクごとに運転挙動が違う |
| 歩行者 | 時間帯が 2 つ以上 / Stochastic でない |
| 横断歩道 | 対応する地図の横断歩道が無い歩行者リンク / 地図の横断歩道を通る車の connection が無い / 両端が同じ待ち場所に近い / 待ち場所が横断歩道の延長線上に無い |
| 歩行者信号 | 1 本の横断歩道に別の信号グループの歩行者信号灯 |
| 信号制御 | 信号プログラムが 2 つ以上 / 車の信号の青点滅 |

## 8. 環境ごとに違ってよいもの

網の作り方と、CARLA・Autoware への渡し方が違うため、次は環境ごとの作りのままにする。結果(どの車がどこを走るか、割合)は同じになるようにする。

| 項目 | 0.9.16 | 0.10 | 理由 |
| --- | --- | --- | --- |
| 網の元 | OpenDRIVE(複数車線の edge) | lanelet2(1 lanelet = 1 edge) | 地図の違い |
| 座標の合わせ方 | Vissim = OpenDRIVE、SUMO = OpenDRIVE + netOffset | 地図座標への変換(transform) | 地図の違い |
| 流入リンク → edge | リンクの中ほどの位置と向き | 流入リンクの終点から 3 m 以内で一番近い edge | 網の違い。確かめ済みの対応付けを使う |
| edge が経路に近いかの判定 | 乗用車が通れる全車線の形 | edge の形 | 網の違い |
| 車線ごとの希望速度決定(S4) | 全車線で同じ分布だけ | 車線ごとに分けてよい | 0.10 の網は 1 車線ずつで、車の車線が決まっている |
| 出力の形 | 車 1 台ずつ`<vehicle>`(出発時刻を決めて書く) | `<route>`と`<flow period="exp(…)">` | 下流(ブリッジ・ブループリント表)が今の形を前提にしている。割合と到着の仕方は同じ |
| CARLA に車体の無い vClass | 無し(バイクも出す) | バイクを割合 0 | CARLA の版の違い |
| 車の信号(6.1 の U3〜U5) | 6.1 | 6.1 | CARLA・Autoware への信号の渡し方の違い |

- 0.9.16 の 3〜5 章は、網を作り直す(横断歩道と歩道を足す)ので、`linkSignalID`の確認、信号プログラムへの歩行者の分の追加、
  sha256 を記録したファイル(`.tll.xml`・`.rou.xml`・ブループリント表)の作り直しが要る。
- 0.9.16 の経路と希望速度決定は、`Town10HD.inpx`に経路決定と希望速度決定を足したもの(テストの中で作る)で確かめた。
  Vissim で作った inpx ではまだ確かめていない。
